# План: сайт-рандомайзер сбалансированных команд

## 1. Общее описание

Одностраничное веб-приложение для формирования сбалансированных команд из списка сотрудников. Участники имеют ФИО, должность (с весом) и прозвище-животное. Система случайно распределяет участников по командам, максимизируя баланс суммарных весов и соблюдая настраиваемые правила совместного/раздельного размещения. Результат можно править вручную переносом участников между командами с мгновенным пересчётом баланса и отчёта.

- **Масштаб**: 10–100 участников, 2–10 команд
- **Данные**: только в браузере (localStorage), без бэкенда
- **Язык интерфейса**: русский
- **Тема**: светлая и тёмная

## 4. Модель данных

```ts
type Position = 'junior-minus' | 'junior-plus' | 'middle-minus'
              | 'middle-plus' | 'senior-minus' | 'senior-plus';

interface Participant {
  id: string;
  fullName: string;      // ФИО
  position: Position;    // должность
  nickname: string;      // «Задумчивый медведь»
}

// Три типа правил:
type Rule =
  | { type: 'together';  a: string; b: string }             // вместе
  | { type: 'separate';  a: string; b: string }             // раздельно
  | { type: 'level-cap'; position: Position; maxPerTeam: number }; // лимит уровня

interface Settings {
  teamCount: number;                     // количество команд
  sizingMode: 'even' | 'limits';         // «поровну» (по умолч.) или min/max
  minSize: number;
  maxSize: number;
  weights: Record<Position, number>;     // настраиваемые веса, дефолт 1–6
  rules: Rule[];                         // каждое можно вкл/выкл
}

interface RuleResult {
  rule: Rule;
  ok: boolean;
  message: string;                       // пояснение, почему нарушено
}

interface DistributionResult {
  teams: { id: string; name: string; memberIds: string[] }[];
  report: {
    ruleResults: RuleResult[];
    balance: { teamId: string; count: number; totalWeight: number; avgWeight: number }[];
    spread: number;                      // разброс сумм весов
  };
}
```

Дефолтные веса: junior minus=1, junior plus=2, middle minus=3, middle plus=4, senior minus=5, senior plus=6 (редактируются в UI).

## 5. Экраны (одностраничник с табами)

### Таб «Участники»
- Таблица: ФИО, должность, прозвище
- Добавление через форму
- Импорт из CSV
- Удаление участника
- Кнопка «другое прозвище» у каждого + общая «обновить все»

### Таб «Настройки»
- Количество команд
- Режим размера: «поровну» (разница ≤ 1 человека) / границы min–max
- Веса должностей: 6 числовых полей
- Конструктор правил:
  - выбор двух людей → «вместе» или «раздельно»
  - должность → «не больше N в команде» (level-cap)
  - список правил с вкл/выкл и удалением

### Таб «Результат»
- Кнопка «Распределить»
- Карточки команд: прозвище, ФИО, должность; сумма и средний вес команды
- **Drag & drop участников между командами** — баланс и отчёт пересчитываются мгновенно
- Панель отчёта: по каждому правилу ✅/❌ с пояснением; общий разброс весов
- При ручном переносе, ломающем правило, — правило сразу подсвечивается красным
- Кнопки «Перераспределить» и «Экспорт CSV»

## 6. Алгоритм распределения (best effort + отчёт)

1. **Валидация**: участников ≥ числа команд, min/max реалистичны, ссылки правил корректны — предупреждения до запуска.
2. **Кластеризация**: правила «вместе» объединяются через union-find → атомарные единицы с суммарным весом и размером. Кластер больше maxSize → фиксируется как заведомо нарушенное правило, разбивается (best effort).
3. **Случайный snake-draft**: единицы с шумом сортируются по весу и раскидываются «змейкой» с учётом лимитов размера и level-cap.
4. **Локальная оптимизация**: hill climbing — обмены и переносы участников, минимизирующие штраф = дисперсия сумм весов + штрафы за нарушения правил. Несколько случайных рестартов, побеждает лучший результат.
5. **Отчёт**: статус каждого правила + причина нарушения; метрики баланса по командам.

## 7. Прозвища-животные

- Словарь ~80 прилагательных (формы м/ж/ср рода) + ~80 животных (с родом)
- Согласование по роду: «Дикая утка», «Задумчивый медведь», «Неопознанный енот»
- Пары прилагательное+животное уникальны в рамках списка
- Кнопка перегенерации у каждого участника и общая «обновить все»

## 8. CSV

### Импорт
- Разделитель `;` или `,` (автоопределение), заголовок необязателен
- Колонки: `ФИО;Должность`
- Должность маппится толерантно (junior/jun/джун…, plus/minus/+/−)
- Нераспознанная должность → дефолт с пометкой для ручного выбора

### Экспорт
- Формат: `Команда;ФИО;Должность;Прозвище;Вес`
- Скачивание файлом, открывается в Excel

## 9. Хранение

- Zustand persist → localStorage
- Сохраняются: участники, настройки (веса, правила), последний результат распределения, выбранная тема
- Кнопка полного сброса данных

## 10. Этапы работ

1. **Каркас**: Vite + React + TS + Tailwind + Zustand, layout с табами, переключатель темы (светлая/тёмная)
2. **Домен**: типы, дефолтные веса, стор с автосохранением
3. **Генератор прозвищ**: словари, согласование родов, уникальность
4. **Таб «Участники»**: CRUD, импорт CSV
5. **Таб «Настройки»**: команды, размеры, веса, конструктор правил (3 типа)
6. **Алгоритм распределения** + unit-тесты (кластеризация, snake-draft, оптимизация, отчёт)
7. **Таб «Результат»**: карточки команд, drag&drop (dnd-kit), live-пересчёт, отчёт по правилам
8. **Экспорт CSV**, полировка обеих тем, сквозная проверка
9. **README** + финальная сборка
